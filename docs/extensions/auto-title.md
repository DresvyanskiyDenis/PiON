# `auto-title` — naming the session

One cheap sub-invocation fired after turn 2, over the first exchange, to set the session display
name.

## Bounded and disposable

- Fired **after turn 2**, not turn 1 — one exchange is rarely enough to name anything.
- Bounded by a 20-second timeout using Node's own timer, because there is no guarantee a `timeout`
  binary exists on the machine.
- **Any** failure — timeout, non-zero exit, dead endpoint — leaves the session carrying on
  untitled. It never fails the turn.

It registers no `tool_call` handler, so the fail-closed/fail-open contract does not apply; the
`try`/`catch` plays the equivalent "our bug must never block the session" role for a `turn_end`
listener.

## Which model titles

The `light` tier of [`routing.json`](../configuration/routing.md#tiers), resolved to a bare
`provider/id` — auto-title shells out to `pi -p --model <id>` rather than dispatching, so it needs
the resolved id and not the tier name.

`PI_TITLE_MODEL` overrides it and is validated: a value that is not a `provider/id` is a typo, and
this module says so rather than running with it.

| Source | Wins when | Reported as |
|---|---|---|
| `PI_TITLE_MODEL` | set to a `provider/id` | `PI_TITLE_MODEL` |
| `routing.json` → `tiers.light.model` | otherwise | `routing.json` |
| neither | the tier map is absent or has no usable `light` | one line, and no titling this session |

On a fresh clone `config/routing.json` does not exist yet — it is generated by `scripts/install.sh`
— so the read falls back to the tracked `config/routing.default.json`. That fallback is deliberate
here and deliberately **absent** from [`dispatch`](dispatch.md), which refuses to run rather than
spend money on a tier map nobody chose. Titling is a six-word throwaway; the shipped default is a
better answer than no titles until you run the installer.

!!! note "Why not a hard-coded model id"
    It used to be one, with a comment arguing that reading the tier map would put a file read on
    the `turn_end` path for a cosmetic feature. The read is once per session, on the one `turn_end`
    that titles. What the literal cost instead is the thing a literal always costs: a model id
    frozen into source outlives the seat, the tier and the catalogue that made it correct, and when
    it stops being served this module has no way to notice.

## Failure is quiet, not silent

The distinction is the whole of this module's failure design. A failed titling attempt never
touches the turn — but it does say so, once, on the one channel the run mode has:

```
[pi-config] auto-title: <model> (from routing.json) returned no usable title — exit 1: <stderr tail>
```

A swallowed failure here is not free. Every attempt spawns a child `pi`, and a child that fails
emits a `provider_failure` of its own — into the channel an operator scans for failures that
matter. A model that stopped being served would keep filing those, every session, while this module
said nothing. A monitoring channel with a permanent known-false entry in it is a broken monitoring
channel.
